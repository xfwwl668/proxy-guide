## 📊 项目总览

### 五个项目定位

| 项目 | 定位 | 部署方式 | 平台 |
|---|---|---|---|
| **sbx-native** | 原生启动器 | FFI 调用 .so | PaaS / 游戏机 |
| **paper-pro** | MC 主文件 | 替换 server.jar | 游戏机 |
| **java-plugins-plus** | MC 插件 | 放 plugins/ 目录 | 游戏机 |
| **Sing-box** | VPS 脚本 | 一键安装 | VPS |
| **deploy-vercel** | Vercel 部署 | npm 部署 | Vercel |

### 核心区别

```
sbx-native:      独立运行，无依赖，原生 FFI
paper-pro:       MC 服务端内置，替换主文件
java-plugins-plus: MC 插件，不影响原 MC 功能
Sing-box:        VPS 一键脚本，全自动安装
deploy-vercel:   Vercel 免费部署，需反代套 CDN
```

## 🔄 信号流程详解

### 翻墙术语表（小白必读）

| 术语 | 英文 | 是什么 | 对应 V2RayN 位置 |
|---|---|---|---|
| **节点** | Node | 代理服务器，帮你转发流量 | 节点列表 |
| **订阅** | Subscription | 节点信息集合，一个链接包含多个节点 | 订阅菜单 |
| **协议** | Protocol | 通信方式，如 VLESS/VMESS/Trojan | 节点详情 |
| **加密** | Encryption | 加密方式，如 AES/ChaCha20 | 节点详情 |
| **TLS** | Transport Layer Security | 传输层安全，加密通道 | 节点详情 security |
| **WS** | WebSocket | 网络套接字，伪装成网站流量 | 节点详情 type |
| **Reality** | Reality | 反检测技术，伪装成正常网站 | 节点详情 flow |
| **HY2** | Hysteria 2 | UDP 协议，速度最快 | 节点详情 protocol |
| **TUIC** | TUIC 5 | QUIC 协议，低延迟 | 节点详情 protocol |
| **CF** | Cloudflare | 全球 CDN 服务，反代加速 | 节点详情 host |
| **Argo** | Argo Tunnel | CF 隧道，流量走 CF 边缘 | 节点详情 port |
| **优选** | Preferred IP | 直连 CDN 边缘，降低延迟 | 节点详情 address |
| **反代** | Reverse Proxy | 域名映射，套 CDN 隐藏 IP | 节点详情 host |
| **CDN** | Content Delivery Network | 内容分发网络，全球加速 | 节点详情 address |
| **哪吒** | Nezha | 节点监控面板 | 节点详情 tag |
| **UUID** | Universally Unique ID | 节点唯一标识 | 节点详情 id |
| **路径** | Path | 访问路径，如 /sub | 节点详情 path |
| **流控** | Flow | 流量控制，如 xtls-rprx-vision | 节点详情 flow |
| **SNI** | Server Name Indication | TLS 握手时的域名 | 节点详情 sni |
| **指纹** | Fingerprint | TLS 指纹伪装 | 节点详情 fp |

│  ┌──────────────────────────────────────────────────────────────────────────────────────────────┐  │

│  │                                                                                                 │  │
│  │  节点做什么？                                                                                   │  │
│  │  1. 接收客户端加密连接（VLESS/VMESS/Trojan/HY2/TUIC）                                      │  │

│  │  3. 通过优选域名/IP 转发（不走被墙的 DNS）                                              │  │

│  │  - Argo：流量走 CF 隧道，不需要开放端口                                                    │  │
│  │  - TG 推送：节点上下线通知                                                                │  │
│  └─────────────────────────────────────────────────────────────────────────────────────────────────┘  │
│         │                                                                                             │
│         │ ③ 通过优选域名/IP 转发                                                                      │
│         │    直连 CDN 边缘节点，不走被墙的 DNS                                                       │
│         ▼                                                                                             │
│  ┌──────────────────────────────────────────────────────────────────────────────────────────────┐  │
│  │                              优选域名 / IP                                                        │  │
│  │  什么是优选？                                                                                    │  │
│  │  - 解析到 CDN 边缘节点的域名或 IP                                                               │  │
│  │  - 延迟低（直连边缘）                                                                           │  │
│  │  - 稳定（避免 DNS 污染）                                                                        │  │
│  │  - 隐藏真实节点（流量经过 CDN）                                                                 │  │
│  │  常用优选：www.google.com / api.github.com / gitee.com / www.visa.com.tw                        │  │
│  │  怎么获取：访问 https://sub.eooce.xx.kg → 选择延迟最低的 → 填入 CFIP 变量                       │  │

│         │                                                                                             │
│         │ ④ 获取目标网站内容                                                                        │
│         │    节点从 CDN 获取 google.com 的内容                                                      │
│         ▼                                                                                             │
│  ┌──────────────┐                                                                                     │
│  │   Google     │  返回内容给节点                                                                     │
│  │   服务器     │                                                                                     │
│  └──────┬───────┘                                                                                     │
│         │                                                                                             │
│         │ ⑤ 加密返回客户端                                                                          │
│         │    内容加密后发回你的电脑                                                                   │
│         ▼                                                                                             │
│  ┌──────────────┐.xml                                                                                     │
│  │   你的电脑    │  浏览器显示 google.com 网页                                                         │
│  │  (客户端)    │                                                                                     │

│                                                                                                       │

#### 3️⃣ 优选域名/IP

```

为什么要优选：
1. 降低延迟 - 直连边缘节点，不走被墙的 DNS
2. 提高稳定性 - 避免 DNS 污染导致超时
3. 隐藏真实节点 - 流量经过 CDN，真实 IP 被隐藏

常用优选域名：
- www.google.com（最常用）
- api.github.com
- gitee.com
- www.visa.com.tw

怎么获取优选：
1. 访问 https://sub.eooce.xx.kg
2. 选择延迟最低的
3. 复制域名/IP
4. 填入节点的 CFIP 变量

V2RayN 节点详情：
- address: 优选域名/IP（节点地址）
- sni: 优选域名（TLS 握手用）
```

#### 4️⃣ 反代 CDN

```
什么是反代：
┌─────────────────────────────────────────────────────────────────────────────┐
│  没有反代：                                                                  │
│  客户端 → 节点真实 IP → 目标网站                                            │
│  问题：节点 IP 暴露，容易被封                                               │
│                                                                             │
│  有反代：                                                                    │
│  客户端 → CF CDN → 节点真实 IP → 目标网站                                   │
│  优势：节点 IP 隐藏，流量经过 CDN，不容易被封                               │
└─────────────────────────────────────────────────────────────────────────────┘

为什么要反代：
1. 套 CDN 加速 - 流量经过 CDN 边缘节点，延迟更低
2. 隐藏真实 IP - 真实节点 IP 被 CF CDN 隐藏
3. 防检测 - 流量看起来像访问正常网站（CF CDN 流量）
4. 防封 - 即使节点被封，换一个域名继续用

怎么反代：
1. 创建 CF Worker（Cloudflare 控制台 → Workers）
2. 粘贴反代代码
3. 绑定自定义域名（如 abc.yourdomain.com）
4. 客户端用新域名连接

反代后的节点信息变化：
┌─────────────────────────────────────────────────────────────────────────────┐
│  字段      反代前                  反代后                                 │
├─────────────────────────────────────────────────────────────────────────────┤
│  address   节点真实 IP              反代域名（CF 域名）                   │
│  host      原域名                   反代域名                             │
│  sni       优选域名                 优选域名（不变）                      │
└─────────────────────────────────────────────────────────────────────────────┘

V2RayN 节点详情：
- address: 反代后的域名（CF 域名）
- host: 反代后的域名
- sni: 优选域名（TLS 握手用）
```

#### 5️⃣ 哪吒面板

```
什么是哪吒：
┌─────────────────────────────────────────────────────────────────────────────┐
│  哪吒是一个服务器监控面板                                                    │
│  显示：连接数、流量、CPU/内存、节点状态                                      │
└─────────────────────────────────────────────────────────────────────────────┘

为什么要用：
1. 监控节点状态 - 知道节点是否在线
2. 统计流量 - 知道用了多少流量
3. 管理多个节点 - 一个面板管理所有节点
4. 故障排查 - 节点不通时看日志

哪吒 v0 vs v1：
┌─────────────────────────────────────────────────────────────────────────────┐
│  版本      配置方式                  端口                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│  v0       NEZHA_SERVER + NEZHA_PORT    需要端口（如 5555）                │

### 常见不通原因和排查

#### 节点打不开？

```
排查步骤：

1. 检查节点是否在线
   - 哪吒面板看节点状态
   - 在线：节点正常，问题在客户端或网络
   - 离线：节点挂了，联系服务器商

2. 检查延迟
   - 点击节点 → 测速
   - 延迟 > 500ms：延迟太高，换节点
   - 超时：节点不通，换节点

3. 检查订阅是否更新
   - 订阅 → 更新所有订阅
   - 节点信息可能过期

4. 检查网络
   - 换网络（WiFi/流量）
   - 换设备测试

5. 检查客户端
   - 更新 V2RayN 到最新版
   - 重启 V2RayN
   - 检查系统代理是否启用

6. 检查节点配置
   - 右键节点 → 信息
   - 检查地址、端口、UUID 是否正确
   - 检查协议是否匹配

7. 检查 CFIP（优选）
   - 节点详情看 address 字段
   - 优选域名可能被墙，换一个
   - 访问 https://sub.eooce.xx.kg 获取新优选
```

#### 哪吒不显示？

```
排查步骤：

1. 检查 NEZHA_SERVER
   - 是否正确填写哪吒面板地址
   - v1 格式：host:port（如 nz.example.com:8008）
   - v0 格式：host（如 nz.example.com）

2. 检查 NEZHA_KEY
   - 是否填写正确密钥
   - 从哪吒面板后台获取

3. 检查 NEZHA_PORT
   - v0 需要填写 agent 端口
   - v1 留空

4. 检查节点备注（tag）
   - 哪吒显示的名称是节点备注
   - 不同节点备注要不同

5. 检查 TLS 自动检测
   - 哪吒端口为 443/8443/2096/2087/2083/2053 时自动开启 TLS
   - 其他端口不开 TLS
```

#### 延迟高？

```
排查步骤：

1. 换节点
   - 选择延迟最低的节点
   - 不同地区延迟不同

2. 换协议
   - HY2/TUIC 速度最快（UDP）
   - VLESS Reality 最稳定（TCP）
   - Trojan 最兼容

3. 换优选域名
   - 访问 https://sub.eooce.xx.kg
   - 选择延迟最低的优选
   - 填入 CFIP 变量

4. 换服务器位置
   - 日本/韩国/新加坡（亚洲）
   - 美国西海岸（北美）
   - 选择离你最近的

5. 检查网络
   - 本地网络问题
   - 换网络测试
   - 换时间测试（高峰期延迟高）
```

#### 流量走了代理但打不开？

```
排查步骤：

1. 检查全局模式
   - 系统托盘 → 全局模式
   - 全局模式：所有应用走代理
   - 应用模式：只有指定应用走代理

2. 检查系统代理
   - 设置 → 启用系统代理
   - 浏览器需要系统代理才能走代理

3. 检查浏览器代理设置
   - 浏览器 → 设置 → 代理
   - 使用系统代理 或 自动检测设置

4. 检查 PAC 文件
   - 设置 → PAC 规则
   - 选择"绕过直连"或"全局代理"

5. 检查节点协议
   - V2RayN 节点详情
   - 协议是否匹配（VLESS/VMESS/Trojan/HY2/TUIC）

6. 检查加密
   - V2RayN 节点详情
   - 加密是否正确（AES/ChaCha20）

7. 检查 TLS
   - V2RayN 节点详情
   - TLS 是否正确（tls/none）
   - SNI 是否正确（优选域名）

8. 检查路径
   - V2RayN 节点详情
   - 路径是否正确（如 /sub）

9. 检查 UUID
   - V2RayN 节点详情
   - UUID 是否正确
   - 不同节点 UUID 不同
```

### 常见设置详解

#### UUID（节点唯一标识）

```
为什么每个节点要唯一：
- 客户端识别节点（区分不同节点）
- 防止节点冲突（UUID 相同会冲突）
- 哪吒监控区分节点

怎么生成：
- 使用在线 UUID 生成器（如 uuidgenerator.net）
- 每个节点随机生成一个
- 格式：xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

V2RayN 节点详情：
- id: UUID（节点唯一标识）
```

#### NEZHA_SERVER / NEZHA_KEY（哪吒监控）

```
哪吒监控什么：
- 连接数（多少人同时用这个节点）
- 流量（上传/下载多少数据）
- CPU/内存（服务器资源使用情况）
- 节点状态（在线/离线）

哪吒 v0 vs v1：
┌─────────────────────────────────────────────────────────────────────────────┐
│  版本      配置方式                    示例                                │
├─────────────────────────────────────────────────────────────────────────────┤
│  v0       NEZHA_SERVER + NEZHA_PORT    nz.example.com + 5555             │
│  v1       NEZHA_SERVER (host:port)     nz.example.com:8008              │
└─────────────────────────────────────────────────────────────────────────────┘

NEZHA_KEY：
- 哪吒面板后台获取
- 每个节点一个 KEY
- 不同节点 KEY 不同

V2RayN 节点详情：
- tag: 节点备注（哪吒显示的名称）
```

#### ARGO_DOMAIN / ARGO_AUTH（Argo 隧道）

```
Argo 隧道是什么：
- Cloudflare 隧道
- 把流量从 CF 边缘节点转到你的服务器
- 不需要开放端口（安全）

临时隧道 vs 固定隧道：
┌─────────────────────────────────────────────────────────────────────────────┐
│  类型      域名                      使用场景                             │
├─────────────────────────────────────────────────────────────────────────────┤
│  临时      每次重启生成新域名          快速测试                            │
│  固定      使用固定域名                长期使用                            │
└─────────────────────────────────────────────────────────────────────────────┘

配置示例：
ARGO_DOMAIN=abc.2go.com
ARGO_AUTH=your-token-or-json

V2RayN 节点详情：
- port: 8001（Argo 隧道端口）
- address: abc.2go.com（Argo 固定隧道域名）
```

#### CFIP / CFPORT（优选域名/IP）

```
优选域名/IP 是什么：
- 解析到 CDN 边缘节点的域名或 IP
- 延迟低（直连边缘）
- 稳定（避免 DNS 污染）

为什么要优选：
1. 降低延迟 - 直连 CDN 边缘节点
2. 避免 DNS 污染 - 不走被墙的 DNS
3. 隐藏真实节点 - 流量经过 CDN

怎么选：
1. 访问 https://sub.eooce.xx.kg
2. 选择延迟最低的
3. 复制域名/IP
4. 填入 CFIP 变量

常用优选：
- www.google.com（最常用）
- api.github.com
- gitee.com
- www.visa.com.tw

V2RayN 节点详情：
- address: 优选域名/IP（节点地址）
- sni: 优选域名（TLS 握手用）
```

#### UPLOAD_URL（订阅上传）

```
订阅上传是什么：
- 把节点信息上传到 Merge-sub
- 一个订阅链接包含所有节点
- 客户端订阅这个链接，自动获取所有节点

为什么要上传：
1. 管理多个节点（一个链接管理所有）
2. 方便客户端订阅（一个链接搞定）
3. 自动更新（节点变化自动更新订阅）

配置示例：
UPLOAD_URL=https://merge.serv00.net

V2RayN 订阅菜单：
- 添加订阅 → 输入订阅链接 → 获取所有节点
```

#### CHAT_ID / BOT_TOKEN（TG 推送）

```
TG 推送有什么用：
- 节点上线通知（节点恢复）
- 节点下线通知（节点挂了）
- 节点流量统计（每天流量）

为什么要推送：
1. 及时发现节点问题（节点挂了立刻知道）
2. 管理多个节点（一个 TG 管理所有）
3. 远程监控（不用登录哪吒）

配置示例：
CHAT_ID=12345
BOT_TOKEN=5678:AA812jqIA...

怎么获取：
1. 找 @BotFather 创建 Bot → 获取 BOT_TOKEN
2. 获取自己的 Chat ID → 填入 CHAT_ID
```

```

export default {
    async fetch(request, env) {
        let url = new URL(request.url);
        if (url.pathname.startsWith('/')) {
            var arrStr = [
                'xxx-xxx.vercel.app',   // 填写你的 Vercel 域名
            ];
            url.protocol = 'https:'
            url.hostname = getRandomArray(arrStr)
            let new_request = new Request(url, request);
            return fetch(new_request);
        }
        return env.ASSETS.fetch(request);

};
function getRandomArray(array) {
  const randomIndex = Math.floor(Math.random() * array.length);
  return array[randomIndex];

## ⚙️ 常见设置详解

### UUID

```
为什么每个节点要唯一：
- 客户端识别节点
- 防止节点冲突
- 哪吒监控区分节点

怎么生成：
- 使用在线 UUID 生成器
- 每个节点随机生成一个
- 格式：xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

### NEZHA_SERVER / NEZHA_KEY

```
哪吒监控什么：
- 连接数
- 流量（上传/下载）
- CPU/内存使用
- 节点状态

哪吒 v0 vs v1：
- v0: 需要 NEZHA_PORT，agent 端口
- v1: 不需要端口，地址格式 host:port

配置示例：
v0: NEZHA_SERVER=nz.example.com, NEZHA_PORT=5555
v1: NEZHA_SERVER=nz.example.com:8008, NEZHA_PORT 留空
```

### ARGO_DOMAIN / ARGO_AUTH

```
Argo 隧道是什么：
- Cloudflare 隧道
- 把流量从 CF 边缘节点转到你的服务器
- 不需要开放端口

临时隧道 vs 固定隧道：
- 临时：每次重启生成新域名
- 固定：使用固定域名，长期使用

配置示例：
ARGO_DOMAIN=abc.2go.com
ARGO_AUTH=your-token-or-json
```

### CFIP / CFPORT

```
优选域名/IP 是什么：
- 解析到 CDN 边缘节点的域名
- 延迟低，稳定性高

为什么要优选：
- 降低延迟
- 避免 DNS 污染
- 隐藏真实节点

怎么选：
1. 访问 https://sub.eooce.xx.kg
2. 选择延迟最低的
3. 填入 CFIP

常用优选：
- www.google.com
- api.github.com
- gitee.com
```

### UPLOAD_URL

```
订阅上传是什么：
- 把节点信息上传到 Merge-sub
- 一个订阅链接包含所有节点

为什么要上传：
- 管理多个节点
- 方便客户端订阅
- 自动更新

配置示例：
UPLOAD_URL=https://merge.serv00.net
```

### CHAT_ID / BOT_TOKEN

```
TG 推送有什么用：
- 节点上线通知
- 节点下线通知
- 节点流量统计

为什么要推送：
- 及时发现节点问题
- 管理多个节点
- 远程监控

配置示例：
CHAT_ID=12345
BOT_TOKEN=5678:AA812jqIA...
```

## ❓ 常见问题解答

### Q1: 哪个项目最适合新手？

**A:** [Sing-box](#4-sing-box) 最适合新手，一键脚本，复制粘贴即可部署。

### Q2: 哪个项目最稳定？

**A:** [Sing-box](#4-sing-box) 最稳定，成熟的一键脚本，多平台支持。

### Q3: 哪个项目最隐蔽？

**A:** [sbx-native](#1-sbx-native) 最隐蔽，原生 FFI，无子进程，不易被检测。

### Q4: 哪个项目最适合免费平台？

**A:** [deploy-vercel](#5-deploy-vercel) 使用 Vercel，完全免费。

### Q5: 哪个项目支持最多协议？

**A:** [sbx-native](#1-sbx-native) / [paper-pro](#2-paper-pro) / [java-plugins-plus](#3-java-plugins-plus) 都支持 6 种协议。

### Q6: 无子进程是什么意思？

**A:** 传统方式启动 sing-box 会生成子进程，容易被检测。[sbx-native](#1-sbx-native) 通过原生 FFI 直接调用动态库，只有一个主进程，更隐蔽。

### Q7: Argo 隧道和固定隧道有什么区别？

**A:** 
- **临时隧道**：每次重启生成新域名，适合快速测试
- **固定隧道**：使用固定域名，适合长期使用

### Q8: 哪吒 v0 和 v1 有什么区别？

**A:**
- **v0**：使用 `NEZHA_PORT`，agent 端口
- **v1**：使用 `NZ_CLIENT_SECRET`，不需要端口，地址格式 `host:port`

### Q9: 如何解锁 GPT 和 Netflix？

**A:** 大多数项目默认配置已解锁，建议使用 VLESS Reality + VMESS WS+Argo 组合。

### Q10: 假人怎么加？

**A:** 
- 用 [paper-pro](#2-paper-pro)：替换主文件后，假人插件放 plugins/ 目录
- 用 [java-plugins-plus](#3-java-plugins-plus)：插件放 plugins/ 目录，假人插件也放 plugins/ 目录
- 推荐插件：Citizens / Dummy Players / FakePlayer
