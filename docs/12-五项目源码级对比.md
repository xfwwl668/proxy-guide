# 12 · 五个项目源码级对比

> 这一篇是把 5 个仓库的源码逐行读完之后写的。不看广告看疗效：它们到底是什么关系、实现上有何本质区别、各自藏着哪些坑。

## 一句话总览

| 项目 | 本质 | 一句话 |
|---|---|---|
| Sing-box 一键脚本 | VPS/免费主机上的 shell 安装脚本 | 在你自己的服务器上装真正的 sing-box，多进程 |
| sbx-native | 单进程启动器（Java/Node/Python 三版） | 把 sing-box 编成 `.so` 塞进一个进程里跑，专为无 root 的容器设计 |
| paper-pro | 魔改过的 Paper 游戏服务端 | 启动器代码直接编译进 `server.jar`，开服即自动跑代理 |
| java-plugins-plus | Minecraft 插件 | 同一套启动器做成插件，丢进 `plugins/` 就寄生运行 |
| deploy-vercel | Vercel 上的 serverless 代理 | 纯手写 Node.js 协议解析，没有 sing-box 内核，必须套反代 |

## 最大的发现：其中三个是同一套代码

`sbx-native` 的 Java 版、 `paper-pro` 的 `App.java`、 `java-plugins-plus` 的 `AppService.java`，方法名 61 个重合，是**同源代码**，区别只在"投递方式"：

| | sbx-native | paper-pro | java-plugins-plus |
|---|---|---|---|
| 运行形态 | 独立进程 | 编译进游戏服务端主 jar | 做成 MC 插件 |
| 谁启动它 | 你自己 `java -jar` | 服务端启动时自动调起 | 插件被服务端加载时调起 |
| 订阅服务 | 自带 HTTP（`/sub`） | 无（靠控制台/`sub.txt`/TG） | 无（同左） |
| 配置方式 | 环境变量 | 改源码默认值后重新构建 | 改源码默认值后重新构建 |

所以这三个选哪个，不看功能（功能一样），看**你手里有什么**：有普通容器选 sbx-native，有 Paper 服要换主文件选 paper-pro，已经有 MC 服不想换主文件选插件版。

## 分项目源码真相

### Sing-box 一键脚本（`xfwwl668/Sing-box`）

- 其实是三套东西：**VPS 版**（要 root，systemd）、**Serv00/CT8 版**（无 root，nohup，1 个 TCP + 2 个 UDP 端口）、**游戏机版**（各语言 HTTP 入口 + 混淆过的 `start.sh`）。
- VPS 版四协议：vless-reality（PORT）、vmess-ws-tls 走 Argo（固定 8001）、tuic（PORT+2）、hysteria2（PORT+3），订阅由 nginx 在 PORT+1 提供。
- Serv00 版没有 vless-reality；UUID 是用户名 md5 派生的（**可预测**），tuic 密码硬编码 `admin123`（全网统一）——**必须手动改**。
- README 里所有一键命令实际拉的是 `eooce/sing-box` 的脚本，不是本仓库快照；且 README 提到的 `2.sh`、`tu.sh` 本仓库里根本没有。
- "默认解锁 GPT 和奈飞"：VPS 版和游戏机版属实（Warp 分流），Serv00 版**不实**（只有 s14/s15/s16 主机分流 google/youtube，没有 netflix/openai 规则）。
- `keep_00.sh` 有变量名拼写 bug（`CFPORT` 写成 `CFIPPORT`，外部传入不生效），`keep.sh` 有语法错误。

### sbx-native（`xfwwl668/sbx-native`）

- 原理：sing-box、cloudflared、哪吒 agent 被编译成 `.so`，主进程用线程加载，`ps` 只能看到一个进程。专为无 root、无 systemd 的 PaaS 容器设计。
- 6 个入站：VMess+WS（恒开）、VLESS Reality、Hysteria2、TUIC、AnyTLS、SOCKS5，后 5 个**填了端口才启用**。
- 三语言实现协议层面完全一致，差异在工程细节：**Node 版最弱**（不支持哪吒 v0，设 `NEZHA_PORT` 会坏；keypair/证书不校验），Java 版最严谨。
- 大坑：`FILE_PATH`、`UUID`、`CFIP` 的默认值**三个实现各不相同**，文档只写了一种；主 README 把 `SHOW_LOG` 写成 `DSHOW_LOG`（拼写错误，源码里是 `SHOW_LOG`）。
- 启动 45 秒后会删掉运行目录里除 `keypair.properties` 和 `sub.txt` 之外的一切（含 `.so`），**每次重启都要重新下载**。
- 保活地址三实现不一致：Python/Java 报到 `oooo.serv00.net`，Node 报到 `keep.gvrander.eu.org`。

### paper-pro（`eooce/paper-pro`）

- PaperMC 的 fork，`App.java` 在服务端启动流程里被调用（`PaperBootstrap.boot()` → 起守护线程跑代理 → 主线程睡 30 秒等你复制订阅 → 清屏 → 正常开服）。
- 构建：改 `App.java` 里环境变量默认值 → push → GitHub Actions 自动编译整个 Paper 服务端 → 从 Release 下载 `server.jar` 覆盖。
- **没有内置 HTTP 订阅服务**。拿订阅 4 种方式：45 秒内从控制台复制（之后清屏）、`world/sub.txt`、TG 推送、`UPLOAD_URL` 上传。
- `FILE_PATH` 默认 `world`（和 MC 存档同名，文件混在里面，45 秒后被清理）。
- 附带行为：启动时会**强制把 `eula.txt` 写成 `eula=true`**（跳过 Mojang 协议确认）。

### java-plugins-plus（`eooce/java-plugins-plus`）

- Maven 多模块：`common` 是全部逻辑，paper/bungee/velocity/fabric 只是薄外壳，`universal` 模块把四者打成**一个通用 jar**，哪个服务端都能用。
- 安装：Paper/Bungee/Velocity 丢 `plugins/`，Fabric 丢 `mods/`，重启即跑。
- 配置方式特殊：JVM 环境变量一般不可控，所以**直接改 `AppService.java` 源码里的默认值**，靠 Actions 把配置"烤进" jar——这就是要求用**私密仓库**的原因（UUID/密钥会进 jar）。
- 伪装：启动 30 秒后打印假的 MC 开服日志（`Preparing spawn area` 等）掩盖代理痕迹；运行目录藏在 `world/` 里。
- README 列的 `ANYREALITY_PORT` 变量**源码里根本不存在**（grep 为 0），别填。

### deploy-vercel（`vvxw/deploy-vercel`）

- **没有 sing-box/xray 内核**。VLESS/Trojan/Shadowsocks 的协议解析是手写的 JS 函数，跑在 Vercel 的 serverless 函数里。
- 只支持 3 种协议，且**全部只走 WebSocket**（同一条路径，靠首字节特征分流），无 UDP、无 Reality。
- Shadowsocks 分支 `method=none`（无加密）且**不校验任何凭证**，访问控制全靠 WS 路径保密。
- `DOMAIN` 是核心变量：不填则订阅退化成 `Vercel出口IP:3000` 的明文链接（公网连不上），**必须填反代后的域名**。反代用 Cloudflare Workers/Snippets 做路径透传即可。
- 默认 UUID 是公开仓库里的公开值，**不改等于把节点送人**（且 WS 路径是 UUID 前 8 位，可推算）。
- `AUTO_ACCESS=true` 会把含 UUID 的订阅链接 POST 给第三方（`oooo.serv00.net/add-url`），README 没提。
- 哪吒 agent 代码虽全，但在 serverless 模型下跑不起来——"哪吒不亮不用填"是结构性必然，不是 bug。

## 怎么选（源码视角）

1. **有 VPS 且有 root**：Sing-box 一键脚本（VPS 版），功能最全，多进程好排错。
2. **只有免费容器/PaaS，无 root**：sbx-native，单进程，选 Java 版最稳（Node 版坑多）。
3. **在玩 MC 服，想顺手跑**：已有服不想换主文件 → java-plugins-plus 插件版；从零搭服 → paper-pro 主文件版。
4. **零成本、能折腾反代、要求不高**：deploy-vercel，接受纯 WS、无 UDP、serverless 限制。
5. **Serv00/CT8 这类免费主机**：Sing-box 的 Serv00 版，但务必手动改 UUID 和 tuic 密码。

## 通用源码级忠告

- 凡是"默认 UUID"都是公开的，不改就是裸奔。5 个项目无一例外。
- `.so` / 二进制都不来自官方 release（`oooen.com`、`2go.us.kg`、`eooce/test` 等个人源），介意供应链安全的自己编译替换。
- 45 秒清理是 sbx 系三项目的共同行为：`sub.txt` 是唯一持久的本地订阅载体，重要节点及时备份。
- TG 推送和 Merge-sub 上传都会把节点明文发给第三方，填之前想清楚。
